# 桌面精灵 AI 助手

新闻与市场行情触发词和数据口径见 [新闻与行情](NEWS-MARKETS.md)。

完整技术实现见 [消息面板技术文档](message-panel-spec.md)（源码基线、窗口/消息链路、兼容性边界与验证计划）。

- 常驻区从上至下显示倒计时、精灵、喝水与聊天按钮；原有下班打卡入口保留。
- 点击聊天按钮显示独立的 344×294 pt 纸色消息窗口；可设为精灵左、右、上、下侧，原生窗口淡入淡出，收起不会取消回复。
- 输入框随内容增高至 88 pt，之后内部滚动。Return / 小键盘 Enter 发送，Shift+Return 换行，中文输入法选词时保留原生键盘处理。
- 在设置 → AI 助手从下拉列表选择 OpenRouter 免费/低价通用对话模型、称谓和 API Key。助手配置立即保存，与工作设置底部保存按钮独立。
- API Key 使用本机应用偏好 `assistant.apiKey` 保存（沙盒版本位于应用容器），不访问钥匙串，不包含在历史导出中。
- OpenRouter 对话请求使用现有 SSE 客户端（`stream: true`，要求 `text/event-stream`），逐块显示文本。可停止请求；失败或中断的部分回复保留，但不作为完整助手回复发送到下一次请求。
- 历史文件：`~/Library/Application Support/OffWorkNow/assistant-history.json`，每个消息含 UUID、时间、角色、文本与完成状态，原子写入。
- 设置页可查看全部历史并通过系统保存面板导出 JSON。发消息时只携带工作时区当天最近最多 6 个完整消息组（普通一问一答或独立主动消息），输入按 UTF-8 字节保守估算，默认输入预算 4096、回复上限 1024 token；可在设置中分别提高到 131072 和 16384，并自动适配模型/供应商容量。
- 每天首次启动保存一条包含称谓、日期、星期和真实天气的双语问候；当天重启仍请求天气但不追加问候，修改称谓不回写旧消息。

验证：`swift test --scratch-path build/assistant-tests`；使用 OffWorkNow macOS scheme 编译。

设置页使用系统 grouped Form。模型列表启动时含已查询的推荐选项，打开 AI 助手 Tab 自动刷新官方目录，并支持手动刷新、缓存及旧模型不可用提示。模型价格筛选上限为每百万 token 输入 $0.30、输出 $1.00；实际费用以返回 usage.cost 为准。SSE usage 存入助手消息并随历史导出，显示单次与本机累计 token/费用，缺失统计不会推断为免费。

发送控件三态：空白草稿显示透明度降低的手绘纸飞机且禁用；有内容显示可发送纸飞机；SSE 接收中显示手绘停止图标，点击取消当前请求并保留已生成内容。
输入法组词期间不向 SwiftUI 发布未提交文本，也不允许 SwiftUI 覆盖原生编辑缓冲；组词提交后同步草稿。
沙盒允许出站网络连接及用户所选导出路径读写。旧钥匙串密钥不会自动迁移，请在设置重新保存。

网络错误显示 HTTP 状态与 API 错误文案。免费模型被 429/502/503 拒绝且尚未收到文本时，仅尝试一次推荐列表内另一个免费通用对话模型，优先不同模型厂商。不会自动使用收费模型。随机免费路由不再作为聊天模型选项或回退目标；审核、分类等专业模型回复保留在历史中但不送入对话上下文。设置页显示实际回复模型。

## 2026-10-16 模型目录更新

以 [OpenRouter 官方实时目录](https://openrouter.ai/api/v1/models) 为准，新增 DeepSeek V4 Flash 0423、V4.1 Flash、V3.2，以及 Qwen3.7 Flash、Qwen3.8 Flash、Qwen3.5-Flash、Qwen3 32B、235B Instruct 和 Coder 30B。另加入两款 1M 上下文的 Nemotron 3.5 免费型号。该次目录未提供 DeepSeek/Qwen 免费型号，不添加已失效的免费 slug。

设置区分模型上下文、当前供应商上下文、模型回复上限以及应用实际请求预算。模型列表升级会合并旧缓存与新增内置项；刷新成功后只展示实时目录中可用且符合价格上限的推荐型号，不改变用户当前选择。Qwen3.7 Flash 的基础费率不代表所有上下文档位，界面会提示分档计价。

对于明确支持关闭可选推理的模型，聊天请求设置 `reasoning.enabled = false`，避免小额输出预算全部消耗在不可见推理上。模型未明确声明支持时不发送该参数。免费模型回退时会重新计算上下文/输出限额和推理参数，始终只回退到免费型号。

模型目录补充了 OpenRouter 免费的 Dots3 Note Preview 和 Nemotron 3 Nano Omni。设置根据官方输入模态标注「视觉」，并展示预览模型的下线日期；旧缓存缺少这些元数据时从内置目录补齐。当前聊天仍仅发送文字，尚未提供图片上传入口。

### 本地文本意图

`AIBot.interpret` 在 API Key 校验和 OpenRouter 请求之前处理文本，返回 nil 才走原有云端聊天。它是确定性的本地规则解析器，不是运行在设备上的大语言模型。

- 饮食：`我今天吃了鸡蛋，喝了牛奶`、`I ate eggs`；按 App 工作安排时区归档，`统计今天的饮食` / `show today diet` 汇总原始记录及条数，不推测热量。
- 提醒：`提醒我14:00创建 App Connect 新版本`、`提醒我明天下午4点回归测试`、`remind me tomorrow at 16:00 to run tests`。时间已过、无效或缺失会本地询问补充；不自动改到下一天。
- 清单：`帮我创建一个 todo checklist` 或 `创建待办清单：发布版本、回归测试`。消息面板的清单组件支持添加、编辑、勾选与删除。

数据独立保存在本机 `assistant.localBot`，提醒同时是可完成的待办。系统定时通知使用 `local.todo.` 前缀；原有提醒清理保留该前缀。权限未开启时显示提示，运行期间仍在消息面板投递；重启时补投未读的到期提醒。系统通知与面板分别承担离线通知和聊天记录，面板只投递一次。新回复沿用消息动画和双语文本，用户输入原文不做翻译。当前仅支持单次提醒，不支持周期提醒、热量估算或任意自然语言推理。

### 按天聊天、启动天气与清单消息

消息面板默认仅显示工作时区当天记录。在顶部下拉（macOS 滚动回弹）或点击「下拉查看更早的聊天记录」按有记录的日期逐天加载，旧日期只在该日第一条消息前标注。加载时保留原阅读位置，浏览旧记录期间不被流式回复拉回底部；「回到今天」或重新打开面板恢复当天视图。输入上下文在 `AssistantContext.build` 内按当前日期过滤，免费模型重试也执行同一过滤规则。

每次启动 `AppModel` 都调用一次本地 AIBot 启动问候，先显示查询中的问候，再用 Open-Meteo 当前天气填充原消息。默认城市上海，可在 AI 助手设置修改；上海使用固定坐标，其他城市先做地理编码。请求绕过缓存、无 OpenRouter 调用和 API Key。天气代码、气温、坐标、观测/请求时间和来源保存在消息的 `weather` 字段；失败记录原因并明确显示天气暂不可用，不使用旧天气冒充本次数据。问候含日期、星期和双语文本。官方文档：https://open-meteo.com/en/docs 和 https://open-meteo.com/en/docs/geocoding-api。

`帮我建一个 todo list`、`帮我建一个 checklist`、`today todo` 等本地输入返回带 `BotChecklist` 的助手消息，卡片内可添加、编辑、勾选和删除，多个清单相互独立，随聊天历史持久化。原来的常驻折叠入口已移除；旧版全局清单迁移至对应的最近清单消息，带时间的提醒保持独立。发送给模型的当天上下文包含清单当前条目和勾选状态。AI 助手设置中的全部聊天记录迁至独立的二级页面，保留返回入口、数量、用量和 JSON 导出。

精灵窗口固定为 240×330，消息面板改为附属的独立 NSPanel，使用原生 alpha 动画淡入淡出。`PetPanelLayout.chatWindowFrame` 根据精灵屏幕坐标计算四方向位置；边缘仅约束消息窗口，不再为展开面板改变精灵窗口尺寸或坐标。移动精灵时附属面板同步跟随，快速开关通过动画代数防止旧关闭回调隐藏新打开的面板。

每日问候按工作时区的日期持久化去重：只有当天第一次启动追加消息，此后启动仍请求并记录真实天气，但不追加问候。兼容旧天气问候识别，面板和模型上下文隐藏同一天的重复问候（原始记录仍保留）。DEBUG 清除当天记录同时清除该日问候标记，下一次启动可重新测试；普通重启不重复问候。最近 365 次成功天气快照保存在本地 `assistant.weatherSnapshots`。

每条消息按实际内容高度与当前消息区可视高度比较，超长消息在自身气泡右下角显示纯图标展开按钮；短消息不显示。按钮随所属消息滚动，点击只打开该条消息，不在面板上放置固定入口。展开为可滚动的完整 Markdown 对话框，直接展示已收到的完整正文，保留代码、表格、文本选择及清单操作，并提供复制全部和关闭。流式消息在对话框内继续更新，不额外发起请求。

待办勾选后使用带删除线的 Text 显示；取消勾选后恢复可编辑的 TextField，避免 macOS 原生文本输入框忽略 SwiftUI 的删除线样式。
